# Sottori ダッシュボード設計 - シンプル化リデザイン

## 概要

ダッシュボードを「3つのシンプルな状態」に基づく大胆な簡素化を実施し、より直感的で段階的な体験設計に変更。

## 設計原則

### 基本方針
- **複雑な4エリア構成** → **シンプルな3段階カード構成**
- **状態による一律表示** → **チャット風の人間的なインタラクション**
- **機能並列表示** → **段階的プロセスガイド**
- **ブランドカラー統一** → **Deep Blue・Warm Coral・Golden Yellow活用**
- **共通コンポーネント最大活用** → **Button・Card variantの適切な使用**

### 体験設計との整合性
新体験フロー「30秒チェック → 3分ロードマップ → あとは自動収集」に完全対応

## UI構成

### 1. チャット風状況確認エリア（最優先）
**位置**: ヘッダー直下の最も目立つエリア
**デザイン**: 
- 人のイラスト（👩‍⚕️）+ 吹き出し形式
- Warm Coral色のアクセント（border-l-warm-coral-400）
- Card variant="elevated" でプレミアム感
- チャットが開くことが直感的にわかるデザイン

**メッセージ例**:
```
「体調や状況の変化はありませんか？
前回は○月○日にロードマップを作成されましたね。」
```

**アクション**: 
- 💬 状況を更新する（Button variant="secondary" + Warm Coral）
- → /status-update ページへ遷移

### 2. 治療ロードマップカード
**位置**: 状況確認の次
**デザイン**: Card variant="default" でスタンダードな表示
**表示内容**:
- 📋 アイコン + タイトル「治療ロードマップ」  
- Deep Blue色のアイコン背景（bg-deep-blue-100）
- 生成日時・時刻の表示
- 生成条件のサマリー（がんの種類・ステージ等）
- 簡潔な説明文

**アクション**:
- 「ロードマップを見る」ボタン（Button variant="primary"）
- → /roadmap ページへ遷移（既存IDまたは最新検索）

### 3. 情報収集状況カード
**位置**: 最下部
**デザイン**: Card variant="outlined" + Golden Yellow枠線
**表示内容**:
- 🔍 アイコン + タイトル「情報収集状況」
- Golden Yellow色のアイコン背景とステータス表示
- 収集済み件数のリアルタイム表示
- 状況に応じたメッセージ表示

**アクション**:
- 「詳細を見る」ボタン（Button variant="outline" + Golden Yellow）
- → /info-updates ページへ遷移

## カラーシステムの統一

### ブランドカラー活用
- **Deep Blue (#556AAB)**: メインアクション、ロードマップ関連
- **Warm Coral (#E69974)**: チャット・コミュニケーション要素
- **Golden Yellow (#F4CB88)**: 情報収集・自動化機能
- **Soft Peach (#FAD8C5)**: サブ要素・背景アクセント

### 従来のgreen系色を完全排除
- ❌ 旧: green-100, green-500, green-50, green-800
- ✅ 新: golden-yellow-100, golden-yellow-500, golden-yellow-50, golden-yellow-800

## 共通コンポーネント最大活用

### Button Component
- **variant="primary"**: メインアクション（Deep Blue）
- **variant="secondary"**: セカンダリアクション（Warm Coral）  
- **variant="outline"**: アウトライン（カスタム Golden Yellow）
- **size="md"**: 標準サイズで統一

### Card Component
- **variant="elevated"**: 最重要カード（チャット風状況確認）
- **variant="default"**: スタンダードカード（ロードマップ）
- **variant="outlined"**: 強調カード（情報収集状況）

## 技術詳細

### UserStateInfo Integration
- first-time: セルフチェック誘導
- has-roadmap: ロードマップ表示 + 状況更新
- returning: 前回データを活用した継続体験

### Data Loading Strategy
```typescript
loadUserState() → getUserState(userId)
loadRoadmapInfo() → getRoadmapHistories(1)  
loadInfoUpdatesStatus() → fetch('/api/info-updates/list')
```

### Router Integration
```typescript
handleStatusUpdate() → '/status-update'
handleViewRoadmap() → '/roadmap?mode=view&roadmapId=${id}'
handleViewInfoUpdates() → '/info-updates'
```

## 継続ユーザー向け状況更新機能

### 問題認識
```
❌ 従来: "状況を更新する" → 初回と同じ5段階質問
✅ 改善後: 前回情報 + 経過時間を踏まえた差分更新
```

### 差分更新設計（実装済み）

#### 1. 前回情報の表示
```
「前回のチェック（○月○日）から○日経ちました」

前回の状況:
- がんの種類: 子宮がん Stage II
- 治療状況: 治療方針検討中  
- 知りたいこと: 治験・臨床試験情報、費用・保険について
- お気持ち: 不安だった、情報を集めたい
```

#### 2. 変化に焦点を当てた3つの質問
- 第1問: 前回から治療の状況に変化はありましたか？
- 第2問: 新たに知りたいことや気になることはありますか？
- 第3問: 前回と比べて、お気持ちの変化はありますか？

#### 3. 効率的な更新フロー
```
変化なし → 簡潔な確認 + 情報アップデート提供
変化あり → 必要な部分のみ詳細質問 + ロードマップ更新
```
