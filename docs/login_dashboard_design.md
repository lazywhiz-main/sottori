## 🎯 設計原則

### **基本理念**
- **安心感の提供**: 「ここにいても大丈夫」という安全基地
- **自然な情報収集**: ユーザーに負担をかけず、必要な情報を自動で収集・整理
- **個別化体験**: その人の状況と感情に寄り添ったパーソナライズ
- **選択可能性**: ユーザーが自分のペースでコントロールできる

### **アプローチ転換**
```
❌ PHRアプローチ（記入中心）
「血液検査の結果を入力してください」
「副作用の詳細を記録してください」

✅ 情報収集・整理支援アプローチ
「今気になっていることに合わせて、必要な情報を集めます」
「あなたの状況を理解して、最適な情報を提案します」
```

## 🎯 情報収集・整理システム設計

### **自動化範囲設計**

#### **ユーザーが教える「気になるポイント」**
```
初回質問（1回のみ）：
「今、一番気になっていることを教えてください」
（複数選択可）

□ 治療選択肢（手術・抗がん剤・放射線など）
□ セカンドオピニオン・専門医
□ 治療費・医療保険・支援制度  
□ 副作用・後遺症
□ 家族への影響・説明方法
□ 仕事・生活の両立
□ 栄養・生活習慣
□ 心のケア・サポート
□ その他（自由記述）
```

#### **サービス側の自動構成**
```
選択された「気になるポイント」に応じて：

🤖 自動収集対象：
- 最新の治療ガイドライン
- 専門医・医療機関データベース
- 治療費・支援制度情報
- 患者体験談（匿名化済み）
- 治験情報
- 最新論文・研究結果

🎯 パーソナライズ条件：
- がん種・ステージ
- 年齢・性別  
- 居住地域
- 治療歴・現在の状況
```

### **動的な情報収集対応**

#### **気になるポイントの変化追跡**
```
治療進行に伴う関心の変化:
診断直後 → 治療選択 → 治療中 → 経過観察

各段階での自動提案:
「治療が始まって1ヶ月が経ちましたね。
 副作用について気になることはありませんか？」

追加情報収集:
□ 副作用対策・生活の工夫
□ 栄養管理・食事療法
□ 精神的サポート
□ 治療継続のコツ
```

## 🔐 プライバシーバランス設計

### **情報セキュリティレベル**

#### **レベル1: 匿名情報（最も安全）**
```
収集データ: がん種、ステージ、年代、地域（都道府県レベル）
利用目的: 一般的な情報提供、統計分析
保護措置: 個人特定不可能な匿名データ
```

#### **レベル2: 仮名化情報（中程度）**
```
収集データ: 治療履歴、症状記録、検査スケジュール
利用目的: パーソナライズされた情報提供
保護措置: 仮名化処理、暗号化保存
```

#### **レベル3: 個人識別情報（最も厳重）**
```
収集データ: 氏名、連絡先、医療機関名
利用目的: アカウント管理、緊急連絡のみ
保護措置: 最高レベル暗号化、アクセス制限
```

### **ユーザー選択可能なプライバシー設定**
```
□ 基本設定（推奨）: レベル1のみ利用
□ パーソナライズ設定: レベル1-2を利用  
□ フルサービス設定: レベル1-3を利用

各設定での機能差異を明確に表示
いつでも設定変更・データ削除可能
```

## 🛠️ 技術実装方針

### **システム構成**
```
フロントエンド: Next.js + TypeScript
バックエンド: Supabase（PostgreSQL + Row Level Security）
AI: OpenAI API（GPT-4）
情報収集: Web Scraping + RSS + API統合
認証: Supabase Auth
```

### **データベース設計**
```sql
-- ユーザー基本情報
users (
  id, email, created_at, updated_at
)

-- がん治療基本情報
cancer_profiles (
  user_id, cancer_type, stage, diagnosis_date, 
  treatment_status, concern_areas, created_at, updated_at
)

-- 気になるポイント管理
user_concerns (
  user_id, concern_type, priority, created_at, updated_at
)

-- 収集情報管理
collected_information (
  id, user_id, concern_type, content, source_url,
  reliability_score, created_at, updated_at
)

-- AI生成コンテンツ管理
ai_generated_content (
  id, user_id, content_type, content, 
  sources, created_at, updated_at
)
```

### **セキュリティ実装**
```
Row Level Security (RLS):
- ユーザーは自分のデータのみアクセス可能
- 管理者権限の厳格な制御

暗号化:
- 保存時: AES-256
- 転送時: TLS 1.3
- 機密データの分離保存

ログ監視:
- 全アクセスの365日保管
- 異常アクセスの自動検知
- プライバシー侵害の監視
```
