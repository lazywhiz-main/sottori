## 🎯 **全体の体験哲学**

**「一人の人間が、迷いながらも、少しずつ前に進んでいく物語」**

がん告知を受けた人は、情報の海で迷子になっている。完璧な答えを求めず、その人のペースで、その人なりの理解で、少しずつ前に進んでいけるような体験を提供する。

---

## 📋 **現在の実装状況分析と改善計画**

### **🎯 企画意図との照合結果**

#### **✅ 企画意図に合致している部分**
1. **ランディングページ（LP）** - コピー「迷っても、頼ってもいい。次の一歩は、あなたのペースで。」が適切に実装
2. **ゆっくりチェック** - チャット形式で「わからない」選択肢を正当化する設計
3. **体験ストーリーの核心価値** - 判断の強要をしない、不完全さを受け入れる姿勢

#### **⚠️ 企画意図からずれている部分**
1. **ナビゲーションの複雑化** - 9つのメニュー項目が多すぎる
2. **ダッシュボードの重複** - `SimpleDashboard`と`PersonalizedDashboard`の二重実装
3. **機能の散在** - 関連機能が複数のページに分散

## 🔧 **具体的な改善点と理由**

### **1. ナビゲーション構造の簡素化**

#### **現在の問題点**
```typescript
// src/components/ui/Header.tsx より
<nav className="flex gap-4">
  <Button>ダッシュボード</Button>
  <Button>セルフチェック</Button>
  <Button>専用ガイド</Button>
  <Button>マイデータ</Button>
  <Button>プロフィール</Button>
  <Button>医療記録</Button>
  <Button>医療チーム</Button>
  <Button>予定</Button>
  <Button>ログアウト</Button>
</nav>
```

#### **改善理由（UXデザイナー視点）**
- **認知負荷の軽減**: 9つの選択肢は人間の認知限界（7±2）を超えている
- **意思決定の簡素化**: 迷いを生む複雑なナビゲーションは企画意図に反する
- **一貫性の欠如**: 企画では「3つのステップ」を強調しているのに、ナビゲーションは9項目

#### **改善案**
```typescript
// 企画意図に沿った3階層構造
<nav className="flex gap-4">
  <Button>🏠 ホーム</Button>           // メインダッシュボード
  <Button>📋 情報整理</Button>         // ゆっくりチェック + 状況更新
  <Button>📚 ガイド</Button>           // ロードマップ + 関連情報
  <Button>⚙️ 設定</Button>             // プロフィール + データ管理
</nav>
```

### **2. ダッシュボードの統合**

#### **現在の問題点**
- `SimpleDashboard`と`PersonalizedDashboard`が並存
- 機能の重複（情報収集状況、ロードマップ表示など）
- ユーザーがどちらを使うべきか迷う

#### **改善理由（UXデザイナー視点）**
- **一貫した体験**: 複数のダッシュボードは混乱を招く
- **段階的開示**: 企画では「自分のペースで」を重視しているのに、複雑な選択を強いている
- **メンテナンス性**: 二重実装は開発・保守コストを増大

#### **改善案**
```typescript
// 統合ダッシュボード（段階的開示）
interface UnifiedDashboard {
  // Phase 1: 基本情報（全ユーザー）
  basicInfo: {
    welcomeMessage: string
    lastCheckDate: Date
    nextSuggestedAction: string
  }
  
  // Phase 2: 個人化情報（利用状況に応じて表示）
  personalizedInfo?: {
    relevantUpdates: InfoUpdate[]
    treatmentProgress: ProgressData
    familySharingStatus: SharingStatus
  }
  
  // Phase 3: 高度機能（必要に応じて表示）
  advancedFeatures?: {
    medicalRecords: MedicalRecord[]
    appointmentManagement: Appointment[]
    teamCommunication: TeamData
  }
}
```

### **3. 体験フローの最適化**

#### **現在の問題点**
```
ランディング → ゆっくりチェック → 結果表示 → サインアップ → ダッシュボード
                                                      ↓
                                              複数のメニュー選択
```

#### **改善理由（企画意図との照合）**
- **迷いの最小化**: 企画では「迷っても、頼ってもいい」と言いながら、複雑な選択を強いている
- **継続性の確保**: 「また来てください」の関係性が複雑なナビゲーションで阻害されている
- **ペースの尊重**: ユーザーのペースを尊重するなら、選択肢は少なく、明確であるべき

#### **改善案**
```
ランディング → ゆっくりチェック → 結果表示 → サインアップ → 統合ダッシュボード
                                                      ↓
                                              段階的な機能開示
```

## 🎯 **企画意図との整合性確認**

### **✅ 核心価値の強化**
- **判断の強要をしない** → ナビゲーション選択肢を4つに削減
- **不完全さを受け入れる** → 段階的な機能開示で「今必要なもの」のみ表示
- **ペースを尊重する** → 複雑な選択を排除し、自然な流れを実現
- **孤独感を和らげる** → 一貫した体験で安心感を提供

### **✅ 体験ストーリーの実現**
- **Phase 1-2**: ランディングとゆっくりチェックは既存の高品質実装を維持
- **Phase 3**: 統合ダッシュボードで「安心できる情報の受け取り」を強化
- **Phase 4**: 段階的開示で「自分のペースでの行動」をサポート

## 📖 **詳細体験シナリオ**

### **1. ランディング（LP）での出会い**

#### **ユーザーの心理状態**
- 「○○がん 治療」で検索を繰り返している
- 情報はたくさんあるが、「私の場合はどうなんだろう？」という不安
- 医学論文は難しすぎる、個人ブログは信頼性が心配
- 「ちゃんと理解できるかな」「間違った判断をしたらどうしよう」

#### **あるべき体験**
- **瞬間的な安心感**: 「迷っても、頼ってもいい」のコピーで「今の私でも大丈夫」
- **プレッシャーの排除**: 「完璧な答えは求めません」「わからないことは、わからないままで大丈夫」
- **行動への優しい誘導**: 「情報を整理してみませんか？」（命令ではなく提案）
- **安全性の保証**: 「無料・匿名OK・いつでも中断できます」

#### **感情の変化**
```
不安・混乱 → 「あ、ここなら大丈夫そう」 → 「試してみようかな」
```

#### **体験の詳細**
- **第一印象（3秒以内）**: サイトを開いた瞬間に「急かされない」「責められない」安心感
- **コピーの受け取り方**: 「迷っても、頼ってもいい」を見て、肩の力が抜ける
- **行動への移行**: 「情報を整理してみる」ボタンを「試してみようかな」という気持ちで押す

---

### **2. ゆっくりチェック（30秒セルフチェック）**

#### **ユーザーの心理状態**
- 「ちゃんと答えられるかな」「間違ったこと言ったらどうしよう」
- 「わからない項目がある...」「まだ検査結果が出てない」
- 「疲れてきた」「一旦やめたい」

#### **あるべき体験**
- **対話的な安心感**: AIが人間らしく、急かさずに話しかけてくる
- **不完全さの受容**: 「わからない」「まだ検査中」が正当な選択肢として扱われる
- **ペースの尊重**: 「疲れたら休憩してください」「途中で保存できます」
- **編集可能性**: 「後で変更できます」「戻って修正できます」

#### **感情の変化**
```
緊張・不安 → 「あ、わからなくても大丈夫なんだ」 → 「自分のペースで進められる」 → 「なんとか答えられた」
```

#### **体験の詳細**
- **開始時の不安**: 「質問に答えられるかな」という不安
- **最初の質問**: 「今、どんな状況でしょうか？」の優しい問いかけ
- **「わからない」の発見**: 選択肢に「わからない」があることで安心
- **途中での疲れ**: 「疲れたら休憩してください」のメッセージで救われる
- **完了時の達成感**: 「なんとか最後まで答えられた」という小さな達成感

---

### **3. チェック結果（簡易ロードマップ）**

#### **ユーザーの心理状態**
- 「なるほど、こういう流れなのか」
- でも「今すぐ決めろと言われても困る」「家族と相談したい」
- 「本当にこの情報を信じていいの？」「私の場合に当てはまる？」

#### **あるべき体験**
- **情報の位置づけ明確化**: 「参考情報として」「相談材料として」
- **決断の強要回避**: 「今日決める必要はありません」
- **信頼性の担保**: 出典を明記「日本がん学会ガイドライン」等
- **継続関係の示唆**: 「迷ったらまた来てください」

#### **感情の変化**
```
「わからない」 → 「なるほど、こういうことか」 → 「でも急がなくていいんだ」 → 「家族と相談してみよう」
```

#### **CTA「もっと詳しく」の意味**
- **単なる機能追加ではない**: 「もっと詳しく知りたい」という自然な欲求への応答
- **関係性の深化**: 「一回限りの情報提供」から「継続的な伴走」へ
- **個人化の始まり**: 「私の状況に合わせて」という期待

#### **体験の詳細**
- **情報の受け取り**: 「3分で読める」「次の3ステップ」という整理された情報
- **信頼性の確認**: 「日本がん学会ガイドライン」の出典で信頼感
- **プレッシャーの回避**: 「今日決める必要はありません」で安心
- **継続への誘導**: 「もっと詳しく」で自然な関係継続

### **4. ログイン後トップ：パーソナライズダッシュボード**

#### **ユーザーの心理状態**
- 「前回の情報、覚えていてくれるかな」
- 「状況が変わったんだけど、どう伝えよう」
- 「今、私が知るべきことは何だろう？」

#### **あるべき体験の詳細**

##### **A. フル治療ロードマップ**
- **前回との連続性**: 「前回お話しした内容は、こちらに保存してあります」
- **変化への対応**: 「何か変わったことがあれば、教えてください」
- **詳細度の選択**: 「今日は詳しく見ますか？概要だけにしますか？」

**体験の詳細**:
- **再訪時の安心**: 「覚えていてくれた」という安心感
- **情報の継続性**: 前回の情報が適切に保持されている
- **更新の自然さ**: 「変わったことがあれば」という自然な問いかけ

##### **B. 状況更新（副作用・検査結果）**
- **自然な会話**: 「調子はいかがですか？」
- **変化の受容**: 「良くなった」「悪くなった」「変わらない」すべて肯定
- **記録の意味**: 「あなたの体験を記録しておくことで、より良い情報を提供できます」

**体験の詳細**:
- **体調への気遣い**: 「調子はいかがですか？」の優しい問いかけ
- **変化の肯定**: どんな変化も「そうなんですね」と受け入れ
- **記録の価値**: 「記録することで、より良い情報を」という意味付け

##### **C. 関連度の高い情報（治験・副作用対処）**
- **タイミングの配慮**: 「今のあなたに関係がありそうな情報です」
- **選択の自由**: 「お時間のある時にご確認ください」
- **情報の質**: 「信頼できる情報源から」「最新の情報を」

**体験の詳細**:
- **関連性の説明**: なぜこの情報が提示されるのかの説明
- **時間的配慮**: 「お時間のある時に」という配慮
- **情報の質保証**: 「信頼できる情報源から」という安心感

##### **D. 目前のアクション一覧（To-Do）**
- **提案のスタンス**: 「こんなことを考えてみませんか？」
- **優先順位の明確化**: 「今すぐ」「今週中に」「余裕のある時に」
- **行動の支援**: 「どうやって進めるか、一緒に考えましょう」

**体験の詳細**:
- **提案の受け取り**: 「命令」ではなく「提案」として受け取る
- **優先順位の理解**: 何を優先すべきかが明確
- **支援の実感**: 「一緒に考えましょう」という伴走感

#### **感情の変化**
```
「覚えていてくれた」 → 「私の状況を理解してくれている」 → 「次に何をすべきか見えてきた」
```

### **5. 通知機能**

#### **ユーザーの心理状態**
- 「忘れていた」「最近見てなかった」
- でも「急かされるのは嫌」「プレッシャーを感じたくない」

#### **あるべき体験**
- **やさしいトーン**: 「お疲れさまです」「お時間のある時に」
- **プレッシャーの排除**: 「急ぎではありません」「お忙しい時は後回しで大丈夫」
- **関係性の維持**: 「変わりがなくても、大丈夫です」

#### **通知の例**
```
「お疲れさまです。一週間が経ちましたが、調子はいかがでしょうか？
特に変わりがなくても、大丈夫です。
お時間のある時に、また顔を出してくださいね。」
```

#### **体験の詳細**
- **通知の受け取り**: 「急かされていない」という安心感
- **関係性の実感**: 「心配してくれている」という温かさ
- **行動の自由**: 「今すぐでなくても大丈夫」という安心

### **6. 自分の治療状況管理**

#### **ユーザーの心理状態**
- 「前に入力した情報、間違っていたかも」
- 「状況が変わったけど、どこを修正すればいい？」
- 「全部やり直すのは面倒」

#### **あるべき体験**
- **簡単な修正**: 「変わった部分だけ教えてください」
- **履歴の保持**: 「以前の記録も残しておきます」
- **変化の肯定**: 「状況が変わるのは自然なことです」

#### **体験の詳細**
- **修正の簡単さ**: 「全部やり直し」ではなく「部分修正」
- **履歴の価値**: 「変化の記録」として意味付け
- **変化の自然さ**: 「変わって当然」という受け入れ

## 🔄 **体験全体を通した一貫性**

### **1. 言葉遣いの一貫性**
- **敬語の使い分け**: 親しみやすいが、適切な距離感
- **肯定的な表現**: 「〜してはいけません」ではなく「〜していただけると」
- **選択の自由**: 「〜してください」ではなく「〜しませんか？」

### **2. 情報提示の一貫性**
- **出典の明記**: すべての情報に信頼できる出典
- **参考情報としての位置づけ**: 決して「指示」ではない
- **医師相談の促進**: 「主治医にご相談ください」を自然に配置

### **3. 関係性の一貫性**
- **継続的な伴走**: 一回限りのサービスではない
- **ペースの尊重**: ユーザーの都合を最優先
- **迷いの受容**: 「迷うのは当然」「頼るのは当然」

## 💭 **体験の「間」と「余白」**

### **急かさない設計**
- **ローディング時間**: 「少しお時間をいただいています」
- **選択の猶予**: 「今日決めなくても大丈夫です」
- **中断の許可**: 「疲れたら、いつでも休憩してください」

### **感情への配慮**
- **落ち込んでいる時**: 「辛い時は、無理をしないでください」
- **前向きな時**: 「その気持ち、大切にしてください」
- **混乱している時**: 「わからないのは、当然です」

### **時間の概念**
- **「30秒」の意味**: 目安であって、1時間かけても良い
- **「3分」の意味**: 理解できなくても、何度でも見返せる
- **「継続」の意味**: いつでも戻ってきて大丈夫

## 🏗️ **必要なページ構成**

### **基本ページ構成（4つの主要ページ）**

#### **1. ランディングページ（/）**
**目的**: 初回訪問者の不安を和らげ、安心してサービスを試してもらう

**主要コンテンツ**:
- ヒーローセクション: 「迷っても、頼ってもいい。次の一歩は、あなたのペースで。」
- 安心感セクション: 「わからない」も立派な回答、途中保存可能、今日決めなくても大丈夫
- 3つのステップ: 眺める → 整理する → また来る
- CTA: 「🌸 情報を整理してみる」

**ユーザーストーリー**:
```
田中さん（50代女性、新規診断）として、

```
```
田中さんとして、
```

## 📋 **実装における重要な考慮事項**

### **ページ構成の原則**
1. **シンプルな選択肢**: 各ページで迷わない設計
2. **明確な次のステップ**: 常に「次に何をすべきか」が分かる
3. **安全な退避**: いつでも前のページに戻れる
4. **状態の保持**: ユーザーの情報と進捗を適切に保存

### **一貫性の確保**
1. **言葉遣い**: 全ページで統一されたトーンとマナー
2. **デザイン**: 安心感を与える一貫したビジュアル
3. **機能**: 似たような機能は同じ場所に配置
4. **フィードバック**: ユーザーの行動に対する適切な反応

## 🎯 **情報アーキテクチャの詳細設計：治療ロードマップとパーソナライズ情報**

*追記日：2025年7月5日*  
*設計根拠：ベテランデザイナーによる認知負荷と利用パターンの分析*

### **📊 設計結論：3階層構造による段階的開示**

**治療ロードマップとパーソナライズ情報は、概要版では統合、詳細版では分離する**

```
1. 統合ダッシュボード（/dashboard）
   ├── 治療ロードマップ（概要版）
   └── パーソナライズ情報（要約版）
   
2. 詳細ページ（分離）
   ├── 治療ロードマップ詳細（/roadmap-detail）
   └── パーソナライズ情報詳細（/info-updates）
```

---

### **🔍 分析根拠：ユーザーの心理状態と情報処理能力**

#### **1. 認知負荷の観点**

**がん患者さんの情報処理特性**
- **診断直後**: 情報処理能力が低下、overwhelmされやすい
- **治療中**: 体調により集中力が変動（薬の副作用、疲労）
- **家族**: 医療知識がない場合が多い、感情的な負担

**→ 一度に大量の情報を見せると、かえって混乱を招く**

#### **2. 利用パターンの根本的違い**

##### **治療ロードマップ**
- **目的**: 全体像の把握、今の位置確認
- **利用頻度**: 週1-2回程度（定期的だが頻繁ではない）
- **閲覧時間**: 5-10分程度（概要版）、20-30分（詳細版）
- **心理状態**: 「今、どこにいるのか知りたい」「全体を理解したい」
- **閲覧パターン**: 通読型（最初から最後まで順番に）
- **情報の性質**: 段階的・順序性のある情報（治療→費用→病院→家族→治験→仕事）

##### **パーソナライズ情報**
- **目的**: 具体的な疑問の解決、最新情報の確認
- **利用頻度**: 必要に応じて（不定期、問題が発生した時）
- **閲覧時間**: 5-10分程度（必要な情報のみ）
- **心理状態**: 「詳しく知りたい」「家族に説明したい」「今困っていることを解決したい」
- **閲覧パターン**: 検索型（必要な情報をピンポイントで）
- **情報の性質**: カテゴリ別・関連度順の情報（20件の動的情報、6つのカテゴリに分散）

#### **3. 現在の実装状況分析**

**治療ロードマップ（`/roadmap`）**
- **構造**: 6つの固定セクション（治療・費用・病院・家族・治験・仕事）
- **内容**: 各セクション3-5項目、総計約20-25項目
- **更新頻度**: 低（ユーザーの状況変化時のみ）
- **データ量**: 中程度（1画面で表示可能）

**パーソナライズ情報（`/info-updates`）**
- **構造**: 6つのカテゴリ（治療・副作用・食事・運動・心理・社会）
- **内容**: 20件の動的情報、各カテゴリ2-5件
- **更新頻度**: 高（日々新しい情報が追加される）
- **データ量**: 大（カテゴリタブでの分割表示が必要）

### **🎯 詳細設計：3階層の情報アーキテクチャ**

#### **Level 1: 統合ダッシュボード（概要版）**

**統合する理由**
- **初回訪問時の認知負荷軽減**: 「どこに何があるか」を一目で理解
- **関連性の可視化**: 治療進捗と個人化情報の関連性を直感的に理解
- **行動への誘導**: 「詳しく見る」への自然な導線

```typescript
interface DashboardOverview {
  // A. 治療ロードマップ（概要版）- 3-4項目に絞る
  treatmentOverview: {
    currentPhase: string        // "手術前の準備期間"
    nextMilestone: string       // "来週火曜日：術前検査"
    progressRate: number        // 進捗率 30%
    detailLink: "/roadmap-detail"
  }
  
  // B. パーソナライズ情報（要約版）- 3件に絞る
  personalizedSummary: {
    urgentUpdates: InfoUpdate[]     // 緊急度高 1件
    relevantUpdates: InfoUpdate[]   // 関連度高 2件
    detailLink: "/info-updates"
  }
  
  // C. 次のアクション（統合）
  nextActions: {
    treatment: string    // "術前検査の準備"
    information: string  // "副作用について確認"
  }
}
```

#### **Level 2: 詳細ページ（分離）**

**分離する理由**
- **情報の性質が根本的に異なる**: 順序性 vs カテゴリ性
- **利用パターンが異なる**: 通読型 vs 検索型
- **更新頻度が異なる**: 低頻度 vs 高頻度
- **認知負荷の分散**: 一度に処理する情報量を制限

##### **A. 治療ロードマップ詳細（`/roadmap-detail`）**

